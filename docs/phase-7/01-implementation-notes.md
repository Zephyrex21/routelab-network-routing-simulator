# Phase 7 implementation notes

## 1. Vite server exposure

The previous configuration bound the Vite development server to `0.0.0.0`, allowing access from other machines on the local network. The Phase 7 configuration binds both development and preview servers to `127.0.0.1`, restricts accepted hostnames to `localhost` and `127.0.0.1`, and explicitly keeps strict filesystem serving enabled.

Vite is pinned to `7.3.8`. The official Vite advisory GHSA-p4f5-76q4-ffq7 was published on 10 November 2026 and lists versions through `7.3.7` as affected; `7.3.8` is the patched 7.x release. The advisory's exploit condition requires the development server to be explicitly exposed to the network, which is why the loopback binding is equally important. Reference: https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7

## 2. Dependency cleanup

- Removed `recharts` because no source file imported it. The Comparison Lab's bars are native CSS elements, so the chart library added install weight without providing functionality.
- Pinned direct dependencies to explicit versions so the first generated lockfile starts from a controlled set: React/React DOM `19.3.1`, React Flow `12.12.1`, React Router DOM `7.18.5`, Lucide React `0.468.0`, Vite `7.3.8`, `@vitejs/plugin-react` `5.1.4`, Tailwind CSS `4.3.5`, and `@tailwindcss/vite` `4.3.5`.
- Avoided major-version upgrades to React Flow 13, React Router 8 and Lucide React 1.x because they are outside this compatibility-focused release.
- Added a Node engine floor of `20.19.0`, compatible with the Vite 7 line used here.

A full npm advisory audit could not be completed in the build environment because package-registry access timed out. The supplied earlier local install output reported four high-severity vulnerabilities, but did not include package/advisory detail. Do not describe the dependency tree as vulnerability-free until `npm audit` has been run locally against the lockfile generated by `npm install`.

## 3. Dialog and mobile navigation accessibility

Dialog surfaces now provide unique labelled/described IDs, make the underlying application inert, lock body scrolling, focus an appropriate control on open, trap Tab navigation, close with Escape and restore focus to the trigger on close.

The mobile navigation drawer now behaves as a modal surface while open. The main column becomes inert, body scrolling is locked, focus stays within the drawer, Escape and the close control dismiss it, and focus returns to the menu trigger. The scrim is decorative to assistive technology; the drawer's explicit close control is the accessible dismissal action.

## 4. Form controls and interaction safety

Reusable `Input` and `Select` components generate stable IDs when a caller does not provide one. Hints and errors are associated through `aria-describedby`; validation errors use `role="alert"`. `IconButton` defaults to `type="button"` to prevent accidental form submissions when placed within forms. Error toasts use assertive `alert` announcements; informational and success toasts use polite `status` announcements, with each message announced atomically.

## 5. Visual accessibility and responsiveness

The light/dark tertiary text tokens are selected to meet a minimum 4.5:1 contrast against the primary page and card surfaces. Keyboard focus styling covers custom elements with a `tabindex`. Existing reduced-motion handling is preserved. Small-screen rules provide larger navigation tap targets, a bottom-sheet dialog layout and 320px-width content safeguards.

The browser's `theme-color` metadata is updated when the theme changes so mobile browser chrome follows the current light/dark theme.

## 6. Import and persistence boundaries

The project import remains capped at 1 MB, parsed as JSON and passed through the strict shared project validator before it can become an active project. Project persistence remains local-only and schema-versioned; no server, analytics or remote upload has been introduced.

## 7. Build limitations

The package registry timed out while generating a new lockfile in the build environment. Therefore this archive pins important direct toolchain versions but does not include a newly generated `package-lock.json`. On the first local `npm install`, retain the generated lockfile in the project directory. The complete production build and browser smoke-test matrix remain required local checks.
